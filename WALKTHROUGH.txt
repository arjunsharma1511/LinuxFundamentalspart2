COMMANDS

REMOTE SESSION

COMMAND 01 | Connect to Cedar
SSH opens a shell on another computer. A login target uses the form user@host. The user is the account name and the host identifies the computer.
Task — Start a simulated session as learner on cedar.example.
1. Read the question. Which command starts the requested remote shell?
2. Select ssh learner@cedar.example
3. Click Check answer. Read the syntax explanation.
   ssh is the program. learner@cedar.example puts the user before @ and the practice host after it.
4. Click the terminal input. Type ssh learner@cedar.example
5. Press Enter or click Run. The terminal label changes to Remote session and the prompt changes from desk to cedar.
6. Click Continue to open the next command.

COMMAND 02 | Check your account
A computer can have several user accounts. The prompt often shows the account name, and a command can confirm it.
Task — Print the current account name.
1. Read the question. Which command prints the current username?
2. Select whoami
3. Click Check answer. Read the syntax explanation.
   whoami takes no argument here. It reports the account attached to your shell.
4. Click the terminal input. Type whoami
5. Press Enter or click Run. Expect learner. The account name and computer name describe different things.
6. Click Continue to open the next command.

COMMAND 03 | Check the computer
A hostname is a computer’s name. After connecting remotely, use it to confirm which machine will receive your commands.
Task — Print the current computer’s name.
1. Read the question. Which command prints the computer name?
2. Select hostname
3. Click Check answer. Read the syntax explanation.
   hostname takes no argument for this check.
4. Click the terminal input. Type hostname
5. Press Enter or click Run. Expect cedar. Compare it with the desk prompt before the connection.
6. Click Continue to open the next command.

COMMAND 04 | Check your location
Your working directory is the folder where relative names are looked up. An absolute path starts with / and names a location from the root.
Task — Print the full path of your current folder.
1. Read the question. Which command prints the working directory?
2. Select pwd
3. Click Check answer. Read the syntax explanation.
   pwd means print working directory. It takes no argument here.
4. Click the terminal input. Type pwd
5. Press Enter or click Run. Expect /home/learner. This is the remote practice account’s home.
6. Click Continue to open the next command.


OPTIONS AND HELP

COMMAND 05 | Read a plain listing
A plain directory listing shows visible names. An option changes how a command behaves. An argument can identify the file or directory to use.
Task — List the visible names in your current directory.
1. Read the question. Which command shows a plain directory listing?
2. Select ls
3. Click Check answer. Read the syntax explanation.
   ls has no options or path here, so it lists the current directory in its default format.
4. Click the terminal input. Type ls
5. Press Enter or click Run. Look for challenge, reports and staff.txt. A name beginning with a dot is hidden from this listing.
6. Click Continue to open the next command.

COMMAND 06 | Reveal hidden names
A filename that starts with a dot is normally hidden in an ordinary listing. The all option includes these names.
Task — List all names in the current directory, including hidden ones.
1. Read the question. Which command adds the all option to a listing?
2. Select ls -a
3. Click Check answer. Read the syntax explanation.
   The -a option means all. The entries . and .. refer to this directory and its parent.
4. Click the terminal input. Type ls -a
5. Press Enter or click Run. Look for .profile. Compare it with the plain listing.
6. Click Continue to open the next command.

COMMAND 07 | Read the long format
A long listing shows metadata such as permissions, owner, group and size. Use it when names alone are insufficient.
Task — List the visible names with their details.
1. Read the question. Which command asks for the long format?
2. Select ls -l
3. Click Check answer. Read the syntax explanation.
   The option -l uses a lowercase letter L. A leading d in the result marks a directory.

5. Press Enter or click Run. Find the owner and group on the staff.txt row.
6. Click Continue to open the next command.

COMMAND 08 | Open a quick help page

COMMAND 10 | Make file sizes readable
File sizes in bytes can be hard to scan. Combine the long and human-readable options to see sizes such as 8.0K.

FILE WORK

COMMAND 12 | Create an empty note
A plain file stores data such as text. One common command creates an empty file when the named file does not yet exist.
Task — Create an empty file at workshop/draft.txt.
1. Read the question. Which command creates the empty file?
2. Select touch workshop/draft.txt
3. Click Check answer. Read the syntax explanation.
   touch creates a file or updates an existing file’s timestamp. The slash places draft.txt inside workshop.
4. Click the terminal input. Type touch workshop/draft.txt
5. Press Enter or click Run. The new file starts with no text.
6. Click Continue to open the next command.

COMMAND 13 | Write one line
echo prints text. A greater-than sign sends that output into a file and replaces the old contents. Use it here on your new draft.
Task — Write Ready for opening into workshop/draft.txt.
1. Read the question. Which command sends the text into the requested file?
2. Select echo "Ready for opening" > workshop/draft.txt
3. Click Check answer. Read the syntax explanation.
   Quotes keep the phrase together. The > symbol redirects output to the path on its right.
4. Click the terminal input. Type echo "Ready for opening" > workshop/draft.txt
5. Press Enter or click Run. A later reading command will show the line. This write itself prints no text in a real shell.
6. Click Continue to open the next command.

COMMAND 14 | Keep a separate copy
A copy creates a second file, allowing you to preserve the original. Give the source first and the destination second.
Task — Copy draft.txt to a new file called copy.txt inside workshop.
1. Read the question. Which command copies the file in the correct direction?
2. Select cp workshop/draft.txt workshop/copy.txt
3. Click Check answer. Read the syntax explanation.
   cp takes the source path first and the new destination path second.
4. Click the terminal input. Type cp workshop/draft.txt workshop/copy.txt
5. Press Enter or click Run. Both draft.txt and copy.txt now exist in the simulated directory.
6. Click Continue to open the next command.

3. Click Check answer. Read the syntax explanation.

5. Press Enter or click Run. The simulator moves the copy to its new name. draft.txt remains separate.
6. Click Continue to open the next command.

USERS AND PERMISSIONS

Task — Check your user ID and groups.
1. Read the question. Which command shows the user ID and groups?

3. Click Check answer. Read the syntax explanation.
   id prints the current identity and relevant group names.

COMMAND 22 | Inspect a file’s access
The permission string starts with the file type, followed by three groups of letters for owner, group and others. r means read, w means write and x means execute.
Task — Read the long listing for staff.txt.
1. Read the question. Which command shows the file’s owner, group and permission bits?
2. Select ls -l staff.txt
3. Click Check answer. Read the syntax explanation.
   The -l option requests the long format. staff.txt limits the listing to that file.
4. Click the terminal input. Type ls -l staff.txt
5. Press Enter or click Run. Expect -rw-------. Only the owner has read and write permission.
6. Click Continue to open the next command.

COMMAND 23 | Grant group read access
A symbolic permission change states who is affected and what to change. The g class represents the owning group. The plus sign adds access.
Task — Give the owning group read access to staff.txt.
1. Read the question. Which command adds read access for the group?
2. Select chmod g+r staff.txt
3. Click Check answer. Read the syntax explanation.
   chmod changes permissions. g selects the group, + adds a permission and r is read.
4. Click the terminal input. Type chmod g+r staff.txt
5. Press Enter or click Run. The simulator adds group read permission. The owner’s access stays the same.
6. Click Continue to open the next command.

COMMAND 24 | Verify the new permissions
After a permission change, inspect the file again. A successful change should appear in the correct group of three characters.
Task — Check the new permission bits for staff.txt.
1. Read the question. Which command verifies the permission change?
2. Select ls -l staff.txt
3. Click Check answer. Read the syntax explanation.
   Use the same long listing as your before check so the permission bits can be compared directly.
4. Click the terminal input. Type ls -l staff.txt
5. Press Enter or click Run. Expect -rw-r-----. The middle triplet is now r--.
6. Click Continue to open the next command.
